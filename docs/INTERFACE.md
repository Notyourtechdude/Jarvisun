# Owner interface

The local FastAPI service serves the interface at `/`, with `/style.css` and `/app.js`. It uses native HTML, CSS, and JavaScript: no Node runtime, remote fonts, trackers, or CDN assets. Open the service in a current browser and paste the owner access token. The token is held in a JavaScript closure for the current page only. Reload, navigation away, disconnect, and HTTP 401 clear it. Private results and inputs are cleared on disconnect. The interface sends bearer authentication headers to same-origin API routes; no token enters a URL or browser storage.

## Daily use

- **Conversation:** ask a question, find a passage, calculate, or describe a next step. Responses show their verification state, kind, sources, and any action receipts. Model inference is clearly labeled unverified. Use Ctrl/Cmd + Enter to send; Enter alone adds a line. Failed messages stay in the composer for retry. Clear conversation removes the page's transcript; it does not delete the server audit.
- **Voice (optional):** expand the Voice disclosure in Conversation to check local transcription and synthesis independently. Upload a 16 kHz mono 16-bit PCM WAV recording up to 30 seconds and 3 MB; the browser validates the format before sending it to `/api/voice/chat`. Transcripts and answers enter the same source/verification view as text. When local synthesis is available, click Listen on an answer to request `/api/voice/speak` and play its WAV using native audio controls. Longer answers explicitly limit speech to the first 1,000 characters. There is no microphone request, browser speech recognition, remote speech service, or browser TTS. Missing engines disable recording submission and explain the unavailable capability.
- **Focus:** choose one small action and 1–180 minutes. Pause, resume, or finish when ready. The local countdown interpolates the server's remaining time; state changes and completed-session counts come from the service. Refresh status reconciles a session after another device changes it. Focus never starts audio or automatic interruptions.
- **Knowledge vault:** update the authorized-folder index, search exact passages, and inspect source paths. Source paths are text, never file links. The graph draws quoted wiki-link relationships and lists full source labels below it. Unresolved references retain their titles; the graph shows at most 40 nodes for legibility, with every returned source listed underneath.
- **Workspace tools:** choose an installed tool, inspect its JSON argument example, run it, and inspect its result and durable job receipt. The UI supports list/read/write files, arithmetic, vault search, business CSV reports, local website creation, and video trimming. Paths are workspace-relative. Installed capabilities do not bypass the server's standing policy. Tool arguments are validated as a JSON object before submission; the server enforces the actual schema and scope.
- **Recurring workflows:** expand the Workspace tools disclosure, choose a tool and arguments above, give the workflow a name, and set an interval of 60 seconds to 30 days. The first run may begin immediately. The service runs it under standing policy while the host is awake and the service is active. Refresh its schedule, inspect arguments/receipts, or pause/resume future runs. An already-running job can finish after pausing. Schedule creation has no client idempotency contract: if the response is ambiguous, refresh the list before scheduling again. Errors remain visible, and the last successful list is retained when a refresh fails. Execution errors are inspected in Activity; supplied workflow `error`/`last_error` values are also displayed.
- **Activity:** refresh jobs and audit events, then expand an event to inspect its structured receipt. Empty states are explicit. If one activity endpoint fails, the other endpoint's successful result remains available.

No examples are injected into the vault, chat, graph, activity, or receipts. Missing engines and unconfigured integrations are shown as unavailable. Service notes from the status endpoint live in an optional disclosure under capability availability.

## Reliability and security behavior

Requests have a two-minute client timeout. Errors include a recovery action where possible. HTTP 401 clears the entire page session; network failures retain the connection and the owner's unsent message so it can be retried. Disconnect aborts in-flight requests, and a session generation check prevents late responses from repopulating private content. Rendering uses text nodes, including SVG graph labels and source names; retrieved HTML is never executed. Audio playback object URLs are revoked and media sources removed on clear/disconnect. Recording buffers and base64 strings are local to the request and released after it; file inputs clear after successful transcription and on disconnect. Playback requires the service CSP to permit `media-src 'self' blob:`.

A failed tool or chat request retains its idempotency key in memory for a retry with unchanged arguments or message. A successful response clears that retry key. If the response is ambiguous, inspect activity before changing the arguments or reloading: reloading deliberately loses in-memory retry state. Chat supplies the service's optional `idempotency_key` field, including for `/do` action requests; workspace tools provide a direct path to a specific write and its receipt.

The interface is designed for 320, 768, 1024, and 1440 px widths. Forms have associated labels, controls are native keyboard targets, section changes move focus to the section heading, errors use an alert region, and chat/focus progress use polite live regions. Motion is disabled under the reduced-motion preference. The source graph has an accessible summary and a textual source list.

## Verification

`uv run pytest tests/test_frontend.py -q` runs four static security/accessibility invariants, one live application asset/authentication/default-voice-status check, and eleven Playwright browser cases, including real rendering at four widths, memory-only authentication, disconnect/401 cleanup, aborted late responses, idempotent retries, literal rendering of hostile markup, sources, focus transitions, tool validation, receipt rendering, network errors, WAV validation/upload, local speech playback cleanup, unavailable voice engines, and workflow scheduling/pause/resume/policy failures. Browser cases use API contract fixtures, not a live external integration. Install Chromium (`uv run playwright install chromium`), or provide the system `chromium` executable, to run them; they explicitly skip if the runtime is unavailable. The local build was checked with `/usr/bin/chromium`; desktop and 320 px screenshots were inspected. A separate actual FastAPI/uvicorn + Chromium smoke check used a temporary vault and workspace and passed authentication, executable calculation, focus start/pause/complete, document indexing/search/graph, verified file creation, job/audit inspection, workflow creation/pause/resume, honest unavailable voice defaults, and disconnect cleanup. Voice transcription/synthesis playback was tested with contract fixtures; actual local engines were not installed or exercised. No production data or external integration credentials were used.

The voice and workflow controls use the service's `/api/voice/chat`, `/api/voice/speak`, and `/api/workflows` contracts, including `/api/workflows/{id}/pause`. No additional API contract changes are required. The UI accepts capability values as `{available, reason}` and reads graph node `id`, `path`, `title`/`label`, and edge `source`/`target`. It reads focus `status`, `remaining_seconds`, `task`, and `moved_today` from the current implementation.
