# Optional packs

These modules are independently callable. The core permission broker must authorize every input/output/model/executable/journal path and outbound effect before invocation. Paths are explicit, files are bounded, and adapters accept no arbitrary destination URLs. No external account was contacted during implementation. Presence of an environment variable means configured, not connected or verified.

| Pack | Callable interface | Result |
| --- | --- | --- |
| Business | `summarize_csv(path, revenue_column='revenue', cost_column='cost', max_rows=10000)` | Rows and exact Decimal revenue/cost/profit as strings; currency remains caller-specified |
| Returns | `score_returns(probability, benefit, cost, expected_loss, privacy_allowed=True, budget=None)` | Hard-constraint eligibility and `probability * benefit - cost - expected_loss` |
| Uncertain returns | `score_returns_range((min,max), (min,max), (min,max), (min,max))` | Conservative minimum/maximum net values from caller-supplied ranges |
| Website | `write_website(path, title=..., description=..., metrics={...}, allow_cdn=False)` | Standalone template HTML business page; escaped data, interactive native projected 3D canvas, offline CSS fallback |
| Video | `render_video(source, destination, start=0, duration=10, captions=[(start,end,text)])` | Verified MP4 cut, 640×360 at 24fps; silent output and timed captions |
| Image | `ImageGenerator(executable=None).generate(prompt, destination)` | Optional local wrapper producing a PNG artifact; unavailable by default |
| Voice | `LocalVoice(whisper_executable=..., whisper_model=..., piper_executable=..., piper_model=...)` | `transcribe(source)` text or `synthesize(text, destination)` WAV; unavailable by default |

Business CSV files are UTF-8, capped at 10 MB, and require unique configured revenue/cost headers. Inputs must use one currency/unit; values are not automatically converted. Decimal parsing rejects NaN/infinity and extreme exponents. Returns probabilities are explicit assumptions, not calibrated model predictions. With uncertain inputs, use ranges.

Website generation uses a fixed business-page template with supplied title, description, and metrics escaped as text. The default includes actual 3D icosahedron vertices and triangular faces rotated mathematically, projected with perspective, sorted by depth, and drawn on a native Canvas 2D surface. It is self-contained and makes no external requests: no library, font, dependency, model, or WebGL runtime is needed. Pointer dragging, arrow keys, labeled rotation buttons, pause/resume, reset, keyboard focus, and a responsive layout are built in. Dragging or manual rotation pauses automatic motion. Reduced-motion preference starts the view paused and changes to that preference pause a running animation; explicit resume remains owner-controlled. A static CSS visual and the business text remain available without JavaScript/canvas. This is a template artifact, with no uniqueness or default WebGL claim; supplied business facts are not inferred or invented.

When explicitly set to `allow_cdn=True`, the artifact visibly labels a pinned external Three.js download from jsDelivr for an optional WebGL enhancement. Native rendering and controls remain the fallback if the download or enhancement fails. System Chromium tests inspect actual canvas pixels, rotate using pointer and keyboard input, verify reset/pause and reduced motion, test mobile width, reject injected business markup, block external requests, and exercise the explicitly enabled CDN failure path. Browser tests render the exact generated HTML with `set_content` because the current system Chromium policy blocks file-URL navigation.

Video requires system FFmpeg/FFprobe. Input limits: 100 MB, 120 seconds, 1920×1080, H.264/MPEG-4/VP8/VP9/AV1. Cuts are at most 30 seconds with at most 20 captions of 200 characters, relative to the cut. Media probe rejects unsupported dimensions/codecs before full decoding; network protocols are disabled. Rendering uses fixed argument arrays (`shell=False`), one decoder/encoder/filter thread, no audio decode, bounded FFmpeg allocations, and 60-second timeout. Captions are written to a private fixed filename, never interpolated into filter syntax. Output is staged, size-checked, probed, and copied only after successful rendering. This is a cut/caption workflow, not an arbitrary editor or an OS sandbox. Reproducibility is within the installed FFmpeg build.

Image generation requires an owner-provided executable wrapper implementing `--prompt TEXT --output PNG_PATH` and an installed local engine/model behind it. The wrapper is trusted executable code and must be broker-authorized. There are no bundled model weights, direct FLUX runtime, API image account, or fabricated fallback images. Output checks bound PNG size/dimensions and inspect its header; they do not establish full semantic image quality.

Voice adapters invoke actual whisper.cpp `whisper-cli` flags (`-m`, `-f`, `-otxt`, `-of`, `-t`) and Piper flags (`--model`, `--output_file`). Models and executables are authorized explicit paths. Input must be uncompressed PCM WAV, at most 20 MB/120 seconds/48 kHz/two channels, with a complete frame payload. For whisper.cpp interoperability, use 16 kHz mono 16-bit WAV. Piper needs its model JSON beside its ONNX model. No audio decompression, online voice account, automatic downloads, or model inference has been demonstrated here.

## Official channels

All constructors accept optional `transport=httpx.MockTransport(...)` for contract tests. Production omits it. Credentials come only from environment variables; do not put secrets into configuration, logs, documents, or UI fields. `available()` returns names of missing variables and `live_verified=False`. It never prints credential values. `ExtensionError` is a safe public failure; underlying service payloads are not exposed. Adapter HTTP logs are suppressed within their request context to prevent the Telegram credential URL from entering httpx logs. Requests use fixed official HTTPS hosts, TLS validation, 15-second timeouts, no environment proxies, no redirects, and bounded response bodies. No browser cookies, account scraping, or detection evasion is used.

- `Telegram(owner_chat_id='123', owner_user_id='123').send(text)` uses `TELEGRAM_BOT_TOKEN` and returns an accepted message receipt. `check_owner(update)` rejects mismatched chat or sender before processing inbound text. If using a group chat, explicitly provide the positive owner user ID as well as the negative chat ID. This module does not expose webhook routes; the caller must authenticate webhook/polling transport. Telegram sends have no adapter journal; the caller must supply durable job idempotency and reconcile uncertain deliveries.
- `WhatsApp(phone_number_id='...', owner_number='+...').send(text)` uses `WHATSAPP_ACCESS_TOKEN` and Meta's official Graph v23 Business API. It sends only to the configured owner. Business account setup, a registered phone number, consent, and Meta's messaging-window rules are deployment prerequisites. Only text inside an authorized messaging window is implemented; template messaging and inbound webhook verification are not implemented. The caller supplies durable job idempotency.
- `Twilio(owner_number='+...', from_number='+...', journal=path, daily_call_cap=2, daily_seconds_cap=120, max_call_seconds=60, daily_message_cap=5)` uses `TWILIO_ACCOUNT_SID` and `TWILIO_AUTH_TOKEN`. `call(text, key=...)` submits inline escaped TwiML with a maximum call duration. `message(text, key=...)` sends an owner-only SMS. `notify(text, key=..., message_fallback=True)` tries a call then sends one idempotent SMS on failure/budget rejection; uncertain call delivery can coexist with the fallback SMS and is labeled. Accepted submission is not proof that a person answered or received a message. Twilio provisioning, verified destinations/trial restrictions, and charges remain owner setup. Daily seconds are conservative reservations, not measured billing or a dollar budget.

## Social publishing

`SocialPublisher(journal_path, daily_cap=3, forbidden_terms=(), transport=None)` implements official Bluesky text posting on `bsky.social`. Set `BLUESKY_HANDLE` and a dedicated `BLUESKY_APP_PASSWORD` in the environment. `publish(text, key='stable-owner-job-key')` creates a session and publishes an `app.bsky.feed.post` record. Text is capped conservatively at 300 Python characters. `set_paused(True/False)` persists the emergency pause. A standing policy consists of the configured account, daily cap, explicit forbidden terms, and broker authorization; this term filter is not a semantic content/moderation classifier. No Mastodon support is claimed.

Twilio and Bluesky reserve SQLite idempotency keys under an immediate transaction before network effects. Duplicate keys with identical payloads return the stored receipt; conflicting payloads fail. Pending/uncertain requests consume daily budget and are never automatically resent. Owner account review and explicit reconciliation are required after an ambiguous delivery; no automatic reconcile endpoint is provided. Budgets use UTC calendar days and persist across process restarts. Use one private durable journal per deployed owner service; deleting it resets the protection. External receipts identify accepted service effects, not final delivery.

Contract tests mock all external accounts. The FFmpeg test creates and renders a real tiny sample when FFmpeg is installed. Voice/image engine wrappers remain unconfigured and report unavailable; no inference quality or external connection claims are implied by passing tests.
